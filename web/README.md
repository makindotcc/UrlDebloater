# Web

Static landing page built with [Zola](https://www.getzola.org/). The cleaner runs from
the WebAssembly build of `urldebloater-urlwasher`.

## Requirements

- Rust with the `wasm32-unknown-unknown` target
- `wasm-pack`
- Zola (included in the repository's Nix dev shell)

Install the Rust tools once:

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-pack
```

## Build

Run from the repository root:

```sh
wasm-pack build crates/urlwasher-wasm --target web --release \
  --out-dir ../../web/static/wasm \
  --out-name urldebloater_urlwasher_wasm --no-typescript
zola --root web build
```

Zola writes the ready-to-deploy site to `web/public`.

`MIXER_URL` is inserted into the page at build time by `get_env` in
`templates/index.html`. When omitted, it defaults to `http://127.0.0.1:7777/`.

For Caddy or another domain, override the configured base URL:

```sh
MIXER_URL=https://twoj-mixer.example/ zola --root web build --base-url https://example.com/
```

The default `base_url` in `zola.toml` is the GitHub Pages project URL.

## Local development

```sh
zola --root web serve
```

Open <http://127.0.0.1:1111>. Zola rebuilds and reloads the page when files change.

Append `?mixer=...` to override the mixer while developing:

```text
http://127.0.0.1:1111/?mixer=http%3A%2F%2F127.0.0.1%3A7777%2F
```

Do not open the generated HTML directly via `file://`. Browsers block ES modules and WASM
loaded from local files.

## Layout

- `templates/index.html` - page template and mixer URL
- `content/_index.md` - root page definition
- `static/styles.css`, `static/app.js` - frontend assets
- `static/wasm/` - generated by `wasm-pack`, ignored by git
- `static/screenshots/` - screenshots used on the page
- `static/assets/icon/logo.svg` - shared logo copied from `assets/icon/logo.svg`
- `public/` - generated output, ignored by git

Rebuild the WASM package after changing `crates/urlwasher` or
`crates/urlwasher-wasm`.
